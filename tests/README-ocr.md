# Free local OCR acceptance checks

Install requirements and run `python scripts/install_ocr_models.py` once. Models
come from the official Tesseract `tessdata_best` repository at a pinned commit,
with SHA-256 verification. Model licensing: Apache-2.0 (see the upstream repo).
The Docker build performs this installation; requests never download models or
send documents to third parties. `LOCAL_OCR_MODELS` can select an installed directory.

On Windows, install and test with the same virtual environment that runs Uvicorn:

```
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe scripts/install_ocr_models.py
.venv/Scripts/python.exe -c "import cv2, pytesseract, pymupdf; print(cv2.__version__)"
.venv/Scripts/python.exe -m unittest discover -s tests -p test_local_preview.py
```

Do not use global Python plus `PYTHONPATH` as a substitute: global packages can
mask a missing dependency in the web server's virtual environment. Missing OCR
dependencies now retain the PDF preview, log the failing stage without document
contents, and return a safe setup-specific message.

Run `python -m unittest discover -s tests -p 'test_*ocr.py'` and
`python -m unittest discover -s tests -p test_local_preview.py`.
Contract tests do not measure recognition accuracy.

For accuracy, manually verify a PDF's values against its image, write a private
JSON mapping of field names to correct values, then run:

```
python scripts/check_ocr_accuracy.py sample.pdf --expected truth.json --output output/ocr_accuracy/report.json --compare-legacy
```

The report separates correct automatic values, incorrect automatic values and
withheld values. Withheld is not counted as correct. The command fails on any
incorrect automatic field. The report contains source SHA-256 and timings.
Do not put customer files, truth manifests or reports in source control.

## Deliberate limits

- The detected single-vehicle TMSTH motor, electric-motor, and fire schedules,
  compulsory-motor (PRB) schedule, and cancellation endorsement layouts are enabled for extraction:
  table-rule structure plus printed
  printed anchor bands must match. The PRB reader splits names, addresses,
  dates and vehicle/premium cells rather than mixing them with logos and clauses. Other
  layouts return a short unsupported-format notice, not unreliable full-page
  OCR text, with all form fields empty.
- Reads at two scales must match; high OCR confidence is not proof of accuracy.
  Names, addresses and combined make/model text remain manual. Never silently
  replace Thai letters or reconstruct a policy number to fit an expected format.
- Display text uses Tesseract's native UTF-8 TXT output, never text reconstructed
  by joining TSV glyph boxes. TXT and confidence TSV are generated by one process
  with the same image/settings. This adapter is tested against pinned pytesseract
  0.3.13, because its public multi-output helper does not accept model/PSM config.
- PRB name lines use PSM 7 at 2x scale for display, with a second 1x read kept as
  evidence. Address blocks use PSM 6. Thai names/addresses still require manual
  review: an improved sample does not justify automatic spelling corrections.
- The four premium amounts are atomic: all must be strict decimal values and
  their sum must match to one satang. No missing value is calculated or guessed.
- Dates must be valid and ordered; their pair is withheld when either fails.
- Vehicle price is not sum insured. No auto-fill of coverage limits from this profile.
- Every candidate still requires human review. `parse_confidence` is zero, not
  a misleading field-completeness percentage. This path cannot qualify for an
  unattended save based on `is_confident`.
- The image tab stays the unmodified page render. Evidence thumbnails are
  unprocessed crops of the deskewed page. The text tab explicitly says it covers
  key fields, not a complete transcription.
- Rendering is capped at 3600px; OCR calls have per-call and total deadlines.
  Preview routes retain their one-worker queue and do not write the database.
- A one-file benchmark does not establish general accuracy or equivalence to
  Google. Test more document layouts before expanding enabled profiles.

## Thai fallback evaluation (2026-09-02)

The full-page Tesseract fallback still misreads Thai names, addresses and some
numbers. Moving the reader or changing whitespace does not resolve recognition.
An isolated `.venv-ocr-eval` trial tested PaddleOCR 3.7.0, PaddlePaddle 3.3.1,
PP-OCRv5_mobile_det and th_PP-OCRv5_mobile_rec against three local scanned PDFs.
It improved detection/reading order and some identifiers, but also introduced
incorrect Thai letters at high reported confidence. Perspective-corrected line
crops reread with Tesseract still lost tone marks. Neither result is accepted as
verified transcription; the experimental engine has NOT been enabled in the app.
Private comparisons are in ignored `output/ocr_accuracy/paddle-trial/`.

CPU inference without MKL took about 22 seconds for the credit note and 47-51
seconds for dense policies in this trial. Enabling MKL failed with a Paddle PIR
attribute error on this Windows runtime. Do not enable the experimental reader
or widen automatic-fill rules just because it returns output or a high score.
